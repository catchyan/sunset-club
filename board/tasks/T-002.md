# T-002 · Everything the first agent will read, made true

- Owner: @A1
- Reviewer: @Q1
- Milestone: M0
- Release condition it advances: M0 — "a deliberately boring pull request goes from dispatch
  to merge with no human touching it". A readiness audit found four documents that would send
  the first agent somewhere that does not exist or is no longer true.

## 1. Goal

An agent that reads this repository's documents and does what they say gets the result the
document promised. Nothing it reads on day one is stale, duplicated, or contradicted
elsewhere.

## 2. Inputs

- `sunset-studio` v3.1.0 — installs launchers so `node tools/lock.mjs` works here
- `docs/02-tech/infra.md` — states the branch protection settings that were the cause of
  andon A-2026-08-21-1, as though they were still correct
- `docs/04-plan/roadmap.md` — M0 exit condition counts the negative tests, and the count is
  wrong
- `docs/03-process/ownership.md` — the fun-audit directory that `feel-spec.md` §8 tells D1 to
  write into is covered by no glob, so the first file written there is out of lane by
  construction
- `board/backlog.md` — claimed to list only unfinished work, while `node tools/board/status.mjs`
  reports a card with no row as an anomaly. Two rules for one file; settled on the dispatch
  branch in favour of the tool, because the tool is the one that will be run
- `AGENTS.md`, `README.md`, `docs/README.md`, `board/README.md` and the comment at the top of
  `.github/workflows/gates.yml` — print the long form of commands that now work in the short
  form the SOPs use

## 4. Contracts

None frozen. v3.1.0 is a minor release: the mount produces four launcher files it did not
before, and no gate changes its verdict.

## 5. Definition of done

- [ ] `.studio-version` reads `v3.1.0` and the mirror verifies against the upstream tag.
- [ ] `node tools/lock.mjs list`, `node tools/board/status.mjs`, `node tools/board/stall.mjs`
      and `node tools/verify-protection.mjs` all run here.
- [ ] Every document in this repository prints one form of those commands, the same form the
      SOPs print. Finished task cards and `board/andon.md` are excluded: they record commands
      that were actually run, at a time when the short form did not exist, and editing a record
      of what happened is not a tidy-up.
- [ ] `infra.md` states no branch protection setting of its own. There is one authority for
      what protection must be, and one tool that reads what it is.
- [ ] `roadmap.md` names no count of negative tests. The list is in `setup.md`; a number
      repeated here is a number that goes stale, and it already had.
- [ ] The ownership table covers the fun-audit directory, and that directory exists.
- [ ] `node tools/board/status.mjs` reports no anomalies.
- [ ] No tracked file this repository owns begins with a byte-order mark.
- [ ] `node docs/_studio/tools/gates/selfcheck.mjs` finds no reference to a path that does
      not exist.

## 6. Acceptance command

```bash
node tools/studio-sync.mjs --remote
node docs/_studio/tools/gates/selfcheck.mjs
node tools/gates/ownership.test.mjs
node tools/board/status.mjs
```

`verify-protection.mjs` is deliberately **not** here, though this card's goal includes it
running. It reads the repository's protection settings, which needs an admin-scoped token, and
an acceptance command that only its author can reproduce is not an acceptance command — the
gatekeeper re-runs these in a clean environment. That check belongs to O1's weekly routine,
which is where the framework puts it.

## 7. Evidence

`evidence/T-002/` — command.txt, output.txt, diff-stat.txt, env.txt.

Plus `launchers.txt`: all four launcher commands run, with their output. That is the finding
this card exists for, and three of the four appear in no other gate.

## 8. Timeout and escalation

- Expected: one session
- If blocked: escalate to @P0. A framework path that does not resolve is a framework problem
  and belongs upstream, not in a workaround here.
- Three failed attempts: stop and write `board/blockers/T-002.md`. There is no fourth.
