# 架构决策记录索引（ADR Index）

> Owner: A1 总架构师 · 格式见 `/sop-adr`
> ADR 是**不可变**的。决定错了不改旧的，写新的取代它。这样"我们当时为什么这么想"才留得下来。

## 什么时候必须写 ADR

- 修改任何 `FROZEN` 契约
- 增删主要技术依赖
- 改变性能预算、网络模型、渲染管线
- 两个 Bot 对同一问题有分歧且各有道理
- 任何"以后可能会后悔"的决定

## 什么时候不用写

- 实现细节（函数怎么拆、变量怎么命名）
- 数值调整（那是内容数据，走 PR 即可）
- 修 bug

> 判据：**别人一年后看到这段代码会不会问"为什么不用更明显的做法"？** 会 → 写 ADR。
